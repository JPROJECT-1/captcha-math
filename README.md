# MathCAPTCHA

**Modern, dynamic, multilingual math-based CAPTCHA for the web.**

MathCAPTCHA is a lightweight, client-side CAPTCHA widget that uses dynamically generated mathematical challenges as a human-verification mechanism.

Instead of image-based CAPTCHA challenges, MathCAPTCHA presents users with mathematical problems across multiple difficulty levels, from basic arithmetic to calculus.

Built with **Vanilla JavaScript (ES6)**, MathCAPTCHA can be integrated into a standard HTML page without requiring a frontend framework.

> **Live Demo & Documentation:**
> https://jproject-1.github.io/captcha-math/

---

## Features

* 🧮 **Dynamic Mathematical Challenges**

  * Generates mathematical questions dynamically.
  * Supports multiple categories of mathematical problems.

* 📊 **7 Difficulty Levels**

  * From basic arithmetic to calculus.
  * Each level focuses on a different mathematical concept.

* 🎲 **Random Difficulty**

  * Use `random` to randomly select a challenge from the available levels.

* 🌍 **9 Interface Languages**

  * Indonesian (`id`)
  * English (`en`)
  * Spanish (`es`)
  * Chinese (`zh`)
  * Japanese (`ja`)
  * Russian (`ru`)
  * French (`fr`)
  * Arabic (`ar`)
  * Hindi (`hi`)

* 🌐 **Automatic Language Detection**

  * `auto-web` detects the language based on the web/browser environment.
  * `auto-user` can be used for user-oriented language detection.

* 🌓 **Dark & Light Mode**

  * Supports `light`, `dark`, and `auto` modes.

* 📦 **Vanilla JavaScript**

  * No frontend framework is required.
  * Designed to work with standard HTML and JavaScript.

* 🔔 **Callback API**

  * Receive events for successful verification, failed attempts, and blocked states.

* 🔢 **Client-Side Verification Token**

  * Successful verification can return a token generated by the client.
  * The token can be passed to application-specific backend logic if additional validation is implemented.

# Quick Start

## 1. Create an HTML5 Document

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">

    <title>MathCAPTCHA Example</title>
</head>
<body>

</body>
</html>
```

## 2. Add the CAPTCHA Container

Add an empty element where the CAPTCHA widget should appear:

```html
<div id="my-captcha-box"></div>
```

## 3. Include MathCAPTCHA

```html
<script src="https://jproject-1.github.io/captcha-math/api.js"></script>
```

## 4. Initialize the CAPTCHA

```javascript
const myCaptcha = new MathCAPTCHA({
    containerId: 'my-captcha-box',

    mode: 'auto',

    language: 'id',

    level: 'random',

    maxAttempts: 5,

    onSuccess: (response) => {
        console.log('Verification successful:', response);

        // Use response.data.token according to
        // your application's verification flow.
    },

    onFail: (response) => {
        console.log('Verification failed:', response);
    },

    onBlocked: (response) => {
        console.log('User reached the maximum attempts:', response);
    }
});
```

# Difficulty Levels

MathCAPTCHA provides **7 mathematical difficulty levels**, each representing a different category of mathematical problems.

|    Level | Category                  | Description                                                        |
| -------: | ------------------------- | ------------------------------------------------------------------ |
|      `1` | Basic Arithmetic          | Basic arithmetic operations.                                       |
|      `2` | Roots & Powers            | Mathematical problems involving roots and powers.                  |
|      `3` | Basic Algebra             | Basic algebraic expressions and equations.                         |
|      `4` | Trigonometry              | Trigonometric problems and calculations.                           |
|      `5` | Probability & Expectation | Probability and expected-value problems.                           |
|      `6` | Vectors                   | Vector problems involving dot products.                            |
|      `7` | Calculus                  | Calculus problems involving derivatives.                           |
| `random` | All Levels                | Randomly selects a challenge from the available difficulty levels. |

### Example

Use a specific difficulty:

```javascript
const captcha = new MathCAPTCHA({
    containerId: 'my-captcha-box',
    level: 4
});
```

Or enable random difficulty:

```javascript
const captcha = new MathCAPTCHA({
    containerId: 'my-captcha-box',
    level: 'random'
});
```

# Configuration

| Parameter     | Type                | Default      | Description                                                                                                     |
| ------------- | ------------------- | ------------ | --------------------------------------------------------------------------------------------------------------- |
| `containerId` | `String`            | `null`       | **Required.** ID of the HTML element where MathCAPTCHA will be rendered.                                        |
| `mode`        | `String`            | `'auto'`     | Display mode: `'light'`, `'dark'`, or `'auto'`.                                                                 |
| `language`    | `String`            | `'auto-web'` | Interface language. Supports `id`, `en`, `es`, `zh`, `ja`, `ru`, `fr`, `ar`, `hi`, `auto-web`, and `auto-user`. |
| `level`       | `Integer \| String` | `'random'`   | Difficulty level from `1` to `7`, or `'random'`.                                                                |
| `maxAttempts` | `Integer`           | `5`          | Maximum number of failed attempts before the CAPTCHA enters the blocked state.                                  |
| `onSuccess`   | `Function`          | —            | Called when the user successfully solves the CAPTCHA.                                                           |
| `onFail`      | `Function`          | —            | Called when verification fails, including when the CAPTCHA is closed by the user.                               |
| `onBlocked`   | `Function`          | —            | Called when the maximum number of attempts is reached.                                                          |

# Callback API

MathCAPTCHA provides three primary callbacks:

```text
onSuccess
onFail
onBlocked
```

## `onSuccess`

Called when the user successfully solves the challenge.

Example:

```javascript
onSuccess: (response) => {
    console.log('Success:', response);
}
```

Example response:

```json
{
    "status": "success",
    "data": {
        "levelPlayed": 4,
        "attemptsUsed": 2,
        "timestamp": "2026-08-24T12:00:00.000Z",
        "token": "..."
    }
}
```

### Token

The `token` returned by `onSuccess` is generated on the client side.

The token is based on encoded verification information using `btoa(...)`, including verification state and related values such as the timestamp and level.

For example, conceptually:

```text
verification state
        +
timestamp
        +
level
        ↓
      btoa()
        ↓
      token
```

> **Security note:** A Base64-encoded value is not encryption and does not provide cryptographic authenticity by itself. The returned token should therefore **not be treated as a cryptographically secure proof of verification**.

If a project integrating MathCAPTCHA requires server-side protection, the developer should implement its own server-side validation and security mechanism.

---

## `onFail`

Called when a verification attempt fails.

This includes an incorrect answer and closing/cancelling the CAPTCHA.

Example:

```javascript
onFail: (response) => {
    console.log('Verification failed:', response);
}
```

Example response:

```json
{
    "status": "failed",
    "reason": "wrong_answer",
    "attemptsUsed": 1,
    "maxAttempts": 5,
    "levelPlayed": 4,
    "timestamp": "2026-08-24T12:00:00.000Z"
}
```

Depending on the event, the `reason` can indicate why the verification failed, such as:

```text
wrong_answer
closed_by_user
```

---

## `onBlocked`

Called after the user reaches the configured `maxAttempts`.

Example:

```javascript
onBlocked: (response) => {
    console.log('CAPTCHA blocked:', response);
}
```

Example response:

```json
{
    "status": "blocked",
    "reason": "wrong_answer",
    "attemptsUsed": 5,
    "maxAttempts": 5,
    "levelPlayed": 4,
    "timestamp": "2026-08-24T12:00:00.000Z"
}
```

### What does "blocked" mean?

The `blocked` state is a **client-side CAPTCHA state**.

When the maximum number of attempts is reached, the current CAPTCHA instance enters the blocked state. To start the CAPTCHA again, the user must refresh the page.

This does **not** mean that the user has been permanently blocked from the website.

MathCAPTCHA itself does not provide an account-level, IP-level, or server-side blocking system.

If permanent or persistent blocking is required, the application developer must implement the appropriate logic on their own backend.

For example:

```text
MathCAPTCHA
    │
    ▼
Maximum attempts reached
    │
    ▼
onBlocked()
    │
    ▼
Client-side blocked state
    │
    ▼
Page refresh
    │
    ▼
CAPTCHA can be started again
```

# Verification Flow

A typical verification flow looks like this:

```text
┌─────────────────────────┐
│      CAPTCHA Starts     │
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│ Generate Math Challenge │
└────────────┬────────────┘
             │
             ▼
       User Answers
             │
       ┌─────┴─────┐
       │           │
     Wrong       Correct
       │           │
       ▼           ▼
  onFail()    onSuccess()
       │           │
       │           ▼
       │         Token
       │
       ▼
Attempts Remaining?
       │
   ┌───┴───┐
   │       │
  Yes      No
   │       │
   ▼       ▼
Retry   onBlocked()
           │
           ▼
      Refresh Page
```

# Client-Side Security

MathCAPTCHA runs primarily on the client side.

This means the JavaScript code, CAPTCHA logic, generated questions, and client-side verification process can potentially be inspected by the user.

Therefore, MathCAPTCHA should not be considered a complete security boundary.

For security-sensitive applications, consider combining MathCAPTCHA with:

* Server-side validation
* Rate limiting
* Request throttling
* Authentication
* Session validation
* Abuse detection
* IP/device controls where appropriate
* A dedicated anti-bot service

The appropriate security architecture depends on the application and its threat model.
